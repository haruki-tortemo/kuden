# 口伝（Kuden）

**職人が話した判断を、次の人が学べる漫画の教本にします。** 職人は、ご飯がちょうどよい時を知っています。でも、その理由を言葉にしたことはほとんどありません。これが暗黙知です。「説明してください」と頼んでも、なかなか出てきません。そこでClaudeが、実際にあった1つの場面について1問ずつ聞き、答えを聞くたびに次の問いを作り直して引き出します。職人は、新人が見落とす判断を1つ話します。それが縦読みの漫画1話になり、海外から来た人を含む若手に届きます。コマを押すと、職人本人の声でその言葉が流れます。吹き出しは、日本語・やさしい日本語・英語・ベトナム語・ポルトガル語に切り替えられます。

Built with Claude: Japan 2026で制作しました。テーマは①「あなたにしかない深さを。」です。[English README](README.md)

**デモ動画:** 準備中

> 現在の状態: 聞き手AIとの聞き取り、漫画づくり、職人の確認画面、静的ページの書き出しまで、ブラウザの1つのタブで最後まで動きます。完成した見本の回は録音を進めています。

## 仕組み

```
録音 ─▶ 書き起こし ─▶ コマ割り ─▶ コマの絵 ─▶ 見直し ─▶ 声の切り出し ─▶ 静的ページ
(手元)    ＋校正        ＋翻訳      (画像)     (3回)      (手元)         (鍵なし)
```

1. **書き起こす:** 録音を手元のMacで文字にし、1語ごとの時刻を持たせます。
2. **校正してコマ割りにする:** 職人言葉の聞き違いを直し、4〜8コマの1話を作ります。新人が困る場面で始まり、職人だけが気づく小さな合図、判断、理由、新人ができるようになったことの順に進みます。職人の吹き出しは録音で話した言葉だけで作り、コードが1語ずつ書き起こしと照らし合わせます。
3. **描く:** 2人の人物と、判断の対象になる材料の見本を描き、その見本を参照して全コマを描きます。絵の中に字は入れません。
4. **見直す:** 描いたコマを3回見ます。話の流れ、人物、細部を1回ずつです。読む人を迷わせる問題だけを描き直しの対象にします。
5. **声を切り出す:** 語の時刻を使って、職人の吹き出しごとに録音から声を切り出します。
6. **確かめる:** 職人と一緒に確認画面を通します。セリフごとに、聞く、直す、録り直す、声を外すができます。校正で直した所は、採用か元に戻すかを選べます。全コマを通すまで公開できません。
7. **書き出す:** サーバーも鍵も要らない静的ページにします。オフラインでも開けます。

## 芯はClaudeの3つの仕事

| | 仕事 | Claudeがすること | 状態 |
|---|---|---|---|
| 1 | **聞き手** | 職人は判断を知っていても、言葉にしていません。録音するだけでは残らないので、引き出す必要があります。Claudeは聞き取りをする人の横で、今の話から作り直した次の1問だけを提案します。質問の一覧を先に渡すと話す人が疲れますし、答えが変われば聞くべきことも変わるからです。進め方はCritical Decision Method（Klein, Calderwood & MacGregor, 1989）に沿っています。難しかった出来事を1つ、口を挟まずに話してもらい、判断の分かれ目と、そこで何を見て、何を比べ、何を選んだかを聞き、最後に新人が見落とす所を聞きます。職人が画面に向かって話すことはありません。 | 動作済み。実際のマイクで試しました |
| 2 | **コマ割り** | 録音を1話にします。新人のつまずき、職人だけが気づく合図、判断と理由の順です。職人の吹き出しは録音の言葉だけを使い、コードが1語ずつ確かめます。 | 動作済み |
| 3 | **3回の見直し** | 描いたコマを3回見ます。話の流れ、見本と比べた人物、手・視線・小物・紛れ込んだ文字です。本当に問題のある所だけを描き直しに回します。 | 動作済み |

書き起こし、絵、声の切り出し、ページは、この3つを支える部品です。

## 決めて確かめるのはClaude、描くのは画像モデル

Claudeは画像を出力できないので、描く工程はGPT-Image-2.5に任せます。何を描くかを決める工程と、描けたかを確かめる工程はClaudeが持ちます。

| | Claude（Opus 5.5） | GPT-Image-2.5 |
|---|---|---|
| **決める** | 1話で教える判断、コマとその順番、立ち位置、作業する手、人物と材料の見た目（見本の説明文として書く） | |
| **渡す** | コマごと、見本ごとに絵の指示を1つ書きます。参照する見本と、そこから写さない物を指定し、絵の中の字を禁じます | 2人の人物と材料の見本を1回描き、それを見て全コマを描きます |
| **確かめる** | 描いたコマを3回見て（話、人物、細部）、問題を「描き直し」と「メモ」に分け、印を付けたコマだけを描き直す命令を出します | 印の付いたコマだけを描き直します |
| **しないこと** | 絵を描くこと | 字を書くこと。吹き出しは別の層なので、職人の言葉と5つの言語は正確なまま保てます |

## Claudeの使い方と、モデルと設定を選んだ理由

| 工程 | モデル | 設定 | 理由 |
|---|---|---|---|
| 書き起こしの校正 | Claude Opus 5.5 | effort high | 聞き違いかどうかの判断には職人の知識と文脈が要ります。mediumでは「米」が「目」になった誤りを見逃しました（`docs/devlog.md` §3）。 |
| コマ割り | Claude Opus 5.5 | effort high、構造化出力、最大3回 | 一番難しい工程です。教える判断を1つに絞り、決まった形に収め、職人の言葉を変えずに残します。毎回、コードで職人の言葉、吹き出しの長さ、構図の変化を確かめます。 |
| コマ割りの批評 | Claude Opus 5.5 | effort medium、別の呼び出し | 作る役と評価する役を分けています。批評役は標語、比喩、事実の足し込みを指摘するだけで、職人の言葉には触れません。 |
| 翻訳 | Claude Opus 5.5 | effort medium | 読み仮名付きのやさしい日本語を含む5言語を1回で訳します。ページの日本語は常に確認済みの原文で、翻訳役の写しは使いません。 |
| 描いたコマの見直し | Claude Opus 5.5（画像を読む） | effort high、3回 | 1話の流れを読み、人物を見本と比べ、手・視線・小物・紛れ込んだ文字を確かめます。 |
| 描く | GPT-Image-2.5 | 見本はmax、コマはhigh | Claudeは画像を出力しません。絵の指示はすべてClaudeが書き、画像モデルが描きます。見本が全コマの見た目を決めるので、見本には最上位の設定を使います。 |
| 書き起こし | whisper.cpp（手元） | | この工程では、職人の声がMacの外に出ません。 |

翻訳と批評をClaude Sonnet 5.5で動かせるかも、同じ回で測りました。Sonnetは2倍速かった一方で、英語の吹き出し19本のうち7本が長さの決まりを超え、ポルトガル語を1行崩し、批評では1件の誤報を出しました。どちらの工程もOpus 5.5のままとした理由です（[`docs/devlog.md`](docs/devlog.md) §4）。この2工程のモデルは設定（`CLAUDE_MODEL_LIGHT`）で切り替えられ、モデルが変わった時は比較（`tools/compare-light-model.ts`）をやり直せます。

Claudeの呼び出しはすべてadaptive thinkingとサーバー側のフォールバックを使っています。まれに断られた時は、同じリクエストの中で別のモデルが引き継ぎます。

| | 役割 |
|---|---|

## 鍵なしで見る

リポジトリをcloneして、ブラウザで`samples/index.html`を開いてください。サーバーも鍵も要りません。コマを押すと話し手の声が流れ、吹き出しは5つの言語に切り替えられます。公開先のページは準備中です。最初の見本は、デモの回を録音して確認を終えてから入れます。見本の入れ方と断る条件は[`samples/README.md`](samples/README.md)にあります。

## 動かす

必要な物: Node.js 24以上（開発は26。TypeScriptをそのまま実行するのでビルドは不要）、ffmpeg、whisper.cpp（`whisper-cli`）と日本語を扱えるモデル。

```bash
npm install
node src/cli.ts all path/to/recording.m4a --ep my-episode --craft 寿司職人
```

聞き取りをその場で行う時は、`node src/cli.ts interview --ep my-episode --craft 寿司職人`を実行し、表示された住所をビデオ通話の横で開きます。「録音を始める」を押すと録音が始まり、話した言葉が文字で流れ、次に聞くことが上に出ます。問いを聞いたら「聞いた」を押してください。終わった後は、`node src/cli.ts all episodes/my-episode/live/recording.webm --ep my-episode`で録音全体を同じ工程に通します。

このリポジトリにcommitする時は、cloneごとに1回、確認の仕組みを有効にしてください。`git config core.hooksPath .githooks`です。作業データ、鍵、ホームのパス、非公開の語が含まれるcommitを止めます。

APIの鍵は、環境変数（`ANTHROPIC_API_KEY`、`OPENAI_API_KEY`）、`~/.secrets/anthropic.env`と`~/.secrets/openai.env`、または[`docs/env.example`](docs/env.example)を写した`.env`（`node --env-file=.env src/cli.ts ...`で読みます）のどれかに置きます。絵の費用をかけずに流れを試す時は`--placeholder`を付けると、コマが名札の付いた箱になります。

公開の前に、職人と一緒に回を確かめます。`node src/cli.ts confirm --ep my-episode`を実行し、表示された住所を開いて、全コマを通したら「公開する」を押します。できたページは`out/<episode>/index.html`にあり、どのブラウザでも開けます。

デモ動画のように1つのタブで最初から最後まで通す時は、`node src/cli.ts demo --ep my-episode --craft 寿司職人`を実行し、表示された住所を開きます。聞き取りが終わったら「漫画にする」を押すと、書き起こし、コマ割り、絵、見直し、描き直し、声の順に進み具合が出て、確認画面へのリンクが現れます。工程はどれも上の命令と同じなので、途中で止まっても続きから作れます。絵の費用をかけずに練習する時は`--placeholder`を付けます。

人の声は、その人のものです。標準では声の切り抜きをページの横に写します。`export --voice-base <url>`を付けると写さず、話し手が同意した保存先から読み込むので、声をこのリポジトリに置かずに済みます。

## 持ち込んだデータ

ありません。見本の職人は架空の人物です。開発中は、試験用に書いた話を音声合成で読み上げたものを使いました。`samples/`の見本は、ハッカソン中に人が役を演じて録音します。
